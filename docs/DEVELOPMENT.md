# Открытие и сборка LOTTO

## Что требуется

- Unity **6000.3.2f1**, установленный через Unity Hub.
- Модуль Windows Build Support для Windows x64.
- Blender **5.2** — только если нужно заново создавать или изменять модели. Для запуска Unity-проекта и сборки игры Blender не требуется.

## Открыть проект

1. Клонируйте репозиторий или распакуйте исходный ZIP.
2. В Unity Hub выберите **Add project from disk** и укажите папку, содержащую `Assets`, `Packages` и `ProjectSettings`.
3. Дождитесь импорта ресурсов и пакетов.
4. Откройте сцену `Assets/Scenes/Salon.unity` и нажмите **Play**.

Салон, билеты, камера и интерфейс создаются игровым кодом при запуске. `Library` Unity создаст самостоятельно.

## Собрать Windows-версию

В редакторе выберите **Velvet Loto → Build Windows game**. Сборщик выполнит проверки и сохранит игру в:

```text
Builds/Windows/VelvetLoto.exe
```

Для запуска сохраняйте рядом папку данных, библиотеки и остальные файлы сборки.

Можно вызвать тот же сборщик из командной строки:

```powershell
& 'C:\Program Files\Unity\Hub\Editor\6000.3.2f1\Editor\Unity.exe' `
  -batchmode -nographics -quit `
  -projectPath 'C:\Projects\Lotto' `
  -executeMethod ProjectBuilder.Build `
  -logFile 'C:\Projects\Lotto\build.log'
```

Пути к редактору и проекту замените своими. Для собственного пути вывода предусмотрен аргумент `-lotoBuildOutput` с полным путём к `.exe`.

## Упаковать для скачивания

После сборки выполните из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\Package-Windows.ps1
```

Будут созданы `dist/LOTTO-Windows-x64.zip` и `dist/SHA256SUMS.txt`. Сценарий сохраняет все файлы Unity-плеера и добавляет краткую инструкцию и лицензии сторонних материалов. Содержимое `dist` предназначено для GitHub Releases и не включается в Git.

Если готовая игра находится в другом месте:

```powershell
.\Tools\Package-Windows.ps1 -BuildDirectory 'D:\Builds\LOTTO'
```

## Устройство проекта

| Путь | Содержимое |
|---|---|
| `Assets/Scripts/LotoRules.cs` | Билеты, личные мешки, выражения и проверка ходов |
| `Assets/Scripts/LotoGame.cs` | Партия, камера, действия, анимации и сетевые сообщения |
| `Assets/Scripts/LanTransport.cs` | TCP-соединения для локальной сети |
| `Assets/Scripts/SalonWorld.cs` | Салон, билеты, материалы и повторное использование бочонков |
| `Assets/Scripts/SalonUI.cs` | Русский интерфейс |
| `Assets/Scripts/SalonAudio.cs` | Короткий карандашный штрих и остальное звуковое сопровождение |
| `Assets/Resources/Expressions.json` | 450 выражений: 90 чисел × 5 ступеней |
| `Assets/Editor/ProjectBuilder.cs` | Проверки, подготовка сцены и Windows-сборка |
| `ArtSource` | `.blend` и сценарий генерации моделей и текстур |
| `docs/screenshots` | Настоящие скриншоты игры |

## Модели Blender

`ArtSource/create_models.py` воспроизводит стол, мешок, бочонок, стул и процедурные текстуры. Сценарий запускается в фоновом Blender:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' `
  --background --python .\ArtSource\create_models.py
```

Он записывает `.blend` в `ArtSource`, а FBX и PNG — в `Assets/Resources`. Для экспорта геометрия объединяется по материалам. После генерации дождитесь повторного импорта в Unity.

## Проверки

При сборке проверяются 500 билетов, четыре режима сложности, возврат пропущенных чисел, завершение партии, отклонение устаревших ходов, направление всех четырёх стульев и двусторонняя передача кириллицы через настоящий TCP-сокет.

Дополнительные диагностические режимы Windows-плеера:

- `-lotoSmoke -captureDir <полный_путь>` — постановка, направления чисел на бочонках, обводка, короткий звук и защита от частых повторов; сохраняет скриншоты и завершает игру.
- `-lotoBenchmark` — сравнение начала партии и сцены с 56 бочонками и обновлениями 4 раза/с. На время замера отключает предел кадров, затем завершает игру.
- `-lotoNetHost` и три экземпляра с `-lotoNetClient` — проверка четырёх игроков через localhost. Эти параметры предназначены для отдельного тестового запуска.

## Ограничения сети

Партия рассчитана на дружескую игру в доверенной локальной сети. Используется TCP-порт **28741**. Решения о ходах принимает ведущий. Ответ текущего бочонка в сетевой снимок не передаётся. Пароль, шифрование, переподключение, сохранение партии и интернет-подбор игроков пока отсутствуют.
